# 四 Tab 信息架构方案

日期：2026-08-13  
约束：底栏固定 4 项；饮食要从「我的」升为完整功能模块。  
状态：已确认并落地。第一项文案保持「首页」，不叫「今日」。

## 问题

现有底栏按「纯衣柜」设计：

`首页 | 我的衣柜 | 穿搭记录 | 我的`

饮食后来做成拍照识热量、身体档案、今日预算、按日流水，已经是第二条日常线，却只在「我的」菜单占一行。分类、标签、身体档案也堆在「我的」，账号页变成垃圾桶。

一级能力实际有 5 个：首页编排、衣柜库存、穿搭日志、饮食日志、账号设置。必须有一样不当 Tab。

## 采用：方案 A · 饮食独立 Tab

底栏：

`首页 | 衣柜 | 穿搭 | 饮食`

拆掉「我的」Tab。账号不是每天要打开的任务；分类/标签属于衣柜，身体档案属于饮食，设置用首页右上角头像进入。

第一项仍叫「首页」，不改成「今日」：它是总入口，不只覆盖「今天」这一天。

### 各 Tab 职责

| Tab | 页面 | 只做什么 |
|-----|------|----------|
| 首页 | `pages/index` | 天气、穿搭建议、今日穿搭摘要、热量一行摘要（点进饮食 Tab）、未记提醒。右上角头像 → 设置 |
| 衣柜 | `pages/wardrobe` | 衣物列表与筛选。次入口：分类、标签 |
| 穿搭 | `pages/outfit` | 穿搭历史与「今日穿搭」 |
| 饮食 | `pages/diet` | 今日热量、记一餐、按日流水。次入口：身体档案 |

### 「我的」里现有入口怎么搬

| 现在 | 搬到 |
|------|------|
| 饮食记录 | 升为 Tab |
| 身体档案 | 饮食页（已有入口） |
| 分类管理 | 衣柜页「分类」 |
| 标签管理 | 衣柜页「标签」 |
| 设置 | 首页头像 → `pages/settings` |
| 登录 / 退出 | 设置页；未登录点头像去登录 |
| `pages/mine` | 不再做 Tab；打开则跳转设置 |

### 首页边界

保留：天气、今日建议、今日穿搭、智能提醒。  
新增：今日热量摘要，`wx.switchTab` 到饮食。  
不要：在首页再嵌饮食列表或衣物网格。
